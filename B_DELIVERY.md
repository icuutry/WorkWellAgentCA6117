# Member B integration notes

B supplies input validation, warning stops, plan validation and workflow orchestration. A provides the interface, C retrieves guidance and calls the selected model, and D persists records and feedback.

## Functions

- `safety.validate_input`: required fields, dates, finite numbers, scores and enums.
- `safety.check_safety`: selected preset warnings stop ordinary advice before retrieval or generation.
- `safety.validate_plan`: one to three actions, exact schema, allowed categories, retrieved source IDs, scope cues and duration checks.
- `workflow.start_workflow`: validation, safety, memory, feedback, retrieval, model, output checks, draft and audit persistence.
- `workflow.submit_decision`: verifies the persisted draft, then saves one explicit final decision and its audit event.

Drafts are saved as awaiting_confirmation with no decision. Accepted and rejected decisions cannot be reversed. Record identity, user, date, input, plan and sources are immutable. The first final decision timestamp is generated by the program. Feedback is reported through a later check-in.

A partial record or audit write returns an error; retry the same decision. Stable record and event IDs prevent duplicates. The interface retains the pending decision and blocks an opposite decision until its save is resolved.

The integrated workflow uses actual C and D implementations. All offline integration plans are visibly labelled; the standalone A UI preview is separate. Pending drafts can be recovered after a session restart by submitting the same check-in without calling the model again.

See SAFETY_RULES.md, PLAN_VALIDATION.md and WORKFLOW_GENERATION.md for rules and limitations. Tests cover invalid inputs, safety stops, retrieval failure, model failure, malformed output, corrupted history, feedback, decisions, stale drafts and partial-write recovery.
